**Read-only image metadata extraction and anomaly flagging** — m3talex parses
JPEG EXIF (via a hand-rolled TIFF/IFD walker) and PNG text chunks using
nothing but the Python standard library, SHA-256-hashes every input into its
report, and flags what a file conspicuously says — or fails to say — about
itself: stripped metadata, editing-software signatures, timestamp
inconsistencies, and synthetic-media indicators.

The premise is simple: "is this image real?" is no longer a gut call, it is a
documentation question. Images arrive as evidence from phones, CCTV exports,
social posts, and increasingly from AI generators, and metadata alone proves
nothing either way. What matters professionally is recording *why* you trust
or distrust an image. m3talex therefore reports findings as observations with
confidence levels — "consistent with post-capture editing," never "fake" — so
a reviewer can see the evidence behind every flag and weigh it themselves.

The tool is one of a suite of four small investigative-documentation tools
built around the same habits: hash everything, timestamp everything in UTC,
never modify an original, and keep the code small enough that a reviewer can
audit the whole thing in one sitting.

> ⚠️ **Authorized use only.** m3talex is intended for lawful, authorized
> investigative documentation work — preserving and evaluating evidence you
> are entitled to handle. It is a defensive documentation tool with no
> offensive, surveillance, or identification capability of any kind: no face
> recognition, no network lookups, no scraping.

## ⚡ Quick start

The repo ships with five deterministic example images under `examples/m3talex/images/`
(a clean phone photo, a Photoshop re-export, a stripped JPEG, a Stable
Diffusion-style PNG, and a GIMP-annotated PNG — all generated byte-by-byte by
`examples/make_examples.py`, no binary blobs of unknown origin).

```bash
# Analyze one image; writes a JSON report to demo-out/single/
python -m m3talex extract examples/m3talex/images/edited_export.jpg -o demo-out/single

# Analyze the whole directory; writes per-image JSON, a Markdown summary,
# and cust0dia-format CSV/JSON manifests to demo-out/batch/
python -m m3talex batch examples/m3talex/images -o demo-out/batch

# Read the batch summary
cat demo-out/batch/m3talex-report.md
```

The extract run flags the Photoshop signature and the modify-vs-capture
timestamp mismatch; the batch run shows all five images with their findings,
each tied to the SHA-256 of the exact bytes analyzed.

## 🧠 What it does

- Extract and preserve image metadata (EXIF tags, PNG text chunks, encoder
  markers) as documented, hashed, per-image JSON reports.
- Flag anomalies as investigative leads: missing EXIF where a camera file
  would have it, editing-software signatures in Software tags, create/modify
  timestamp inconsistencies, and synthetic-media indicators such as generator
  parameter blocks.
- Produce a batch Markdown report plus manifests in the shared
  cust0dia format, so results slot into a chain-of-custody workflow.
- Record reasoning, not verdicts — every finding is an observation with a
  confidence level and quoted evidence.

### What this demonstrates

Building m3talex meant writing a bounds-checked binary parser for two image
formats directly against their specifications — no PIL, no exifread, no
dependency to hide behind. It evidences comfort with low-level byte-level
formats, with designing for untrusted input (loop guards, CRC validation,
graceful degradation on corrupt entries), and with the discipline of
evidence handling: hash everything, timestamp everything in UTC, never
touch the original, and phrase findings so a reviewer can audit the
reasoning rather than trust a verdict.

## 🔒 Security model

- **Standard library only.** Zero third-party dependencies, including for
  image parsing — the JPEG/TIFF and PNG walkers are implemented directly, so
  the most security-sensitive code path (parsing untrusted bytes) carries no
  supply-chain surface.
- **Fully offline.** No network calls of any kind, ever. There is no network
  code in the repository.
- **Read-only on inputs.** Inputs are only ever opened for reading, and the
  CLI refuses to write its reports into (or beneath) the evidence directory
  it was pointed at.
- **Small and auditable.** Twelve focused modules, heavy documentation,
  bounds-checked binary parsing with loop guards — the entire tool can be
  read end-to-end in well under an hour.

## 🛠 Install

Requirements: **Python 3.11+** and nothing else.

```bash
git clone https://github.com/v0idravl/chr0nix.git
cd chr0nix
python -m m3talex --help
```

There is no install step, no build, and no dependency resolution — run the
package in place with `python -m m3talex` from the repository root.

## Usage

### `extract` — analyze one image

```bash
python -m m3talex extract path/to/image.jpg -o reports/single
```

Parses one JPEG or PNG (format is detected from magic bytes, not the
extension), hashes it, evaluates all anomaly heuristics, prints a summary to
stdout, and writes a full JSON report (`<name>.meta.json`) to the output
directory. The output directory must not be inside the image's own directory.

### `batch` — analyze a directory of images

```bash
python -m m3talex batch path/to/case-images -o reports/batch
```

Recursively finds every `.jpg`/`.jpeg`/`.png` under the directory and writes:

- one JSON report per image (filenames encode the relative path, so
  same-named files in different subdirectories never collide);
- `m3talex-report.md` — a human-readable summary table plus per-image
  findings, notes, and parse warnings;
- `manifest.csv` and `manifest.json` — SHA-256 manifests of every discovered
  image in the shared cust0dia format
  (`relative_path,size_bytes,sha256,mtime_utc,hashed_at_utc`).

A corrupt or unparseable image does not sink the batch: it is reported to
stderr, still hashed into the manifest, and the run continues.

### Common options

- `-o, --outdir` — default: `./m3talex-output`. Output directory.
  Created if missing; refused if it is the evidence directory or inside
  it.
- `--version` — default: —. Print the tool version.

Exit codes:

| Code | Meaning |
|------|---------|
| `0` | Success. |
| `1` | Expected failure (bad input, refused output path, unparseable image). |
| `2` | Argument-usage errors. |

## ✅ Current capabilities

1. **Stdlib JPEG/EXIF parsing.** A bounds-checked TIFF/IFD walker decodes
   IFD0, the EXIF sub-IFD, and the GPS sub-IFD out of the APP1 segment;
   the JPEG walker also records JFIF presence, COM comments, SOF dimensions,
   and progressive-scan encoding, and stops at SOS rather than reading pixel
   data.
2. **Stdlib PNG parsing.** A chunk walker decodes IHDR and all three text
   chunk types (tEXt, zTXt with zlib decompression, iTXt), validates CRCs,
   and records mismatches as warnings instead of failing the file.
3. **Anomaly heuristics with confidence levels.** Missing EXIF where
   expected, EXIF without camera identity, editing-software signatures,
   generator-tool signatures, modify-predates-capture timestamp
   inconsistencies (high confidence), modify-differs-from-capture mismatches,
   digitization mismatches, file-mtime cross-checks, and synthetic-media
   fingerprints in PNG text keywords. Every finding quotes its evidence.
4. **Integrity-first reporting.** Every input is SHA-256-hashed into its
   report; batch mode additionally emits the shared cust0dia
   CSV/JSON, with rows sorted by relative path so outputs diff cleanly
   across runs. All timestamps are UTC ISO-8601.
5. **Safety rails.** Format detection by magic bytes, loop-guarded sub-IFD
   traversal, graceful degradation on corrupt entries, refusal to write into
   the evidence directory, and a defensive guarantee that no code path opens
   an input for writing.

## ⚠️ Known limitations

- JPEG and PNG only. HEIC, WebP, TIFF-as-image, and video containers are out
  of scope for now.
- The example JPEG fixtures carry metadata segments but no scan data; the
  parser never needs pixels, so neither do the tests.
- Heuristics are pattern-based, not cryptographic. A stripped or re-tagged
  file can look perfectly clean, and a camera that writes a Software tag can
  look edited. The confidence levels exist precisely because metadata is
  suggestive, not proof — the tool documents leads, it does not authenticate.
- EXIF maker notes, thumbnail IFDs, and XMP sidecar data are not parsed.
- GPS coordinates are reported raw (as stored) rather than converted to
  decimal degrees.
- PNG files have no EXIF, so "missing metadata" is only meaningful for JPEG.

## 📝 Notes

- Findings are phrased as observations ("consistent with …") deliberately.
  If you ever see this tool's output quoted as a verdict, that is a misuse
  of the report.
- `examples/make_examples.py` regenerates the demo images deterministically;
  the same builder module (`m3talex.samplegen`) builds the test fixtures,
  so every binary the tests parse is knowable by construction.
- `m3talex-output/`, `demo-out/`, and `out/` are git-ignored; reports are
  regenerated artifacts, not source.
- m3talex is intended for lawful, authorized investigative documentation
  work only — preserving and evaluating evidence you are entitled to handle.
  It contains no offensive, surveillance, or identification capability of
  any kind: no face recognition, no network lookups, no scraping.
- Run the tests with `python -m unittest` from the repository root.
